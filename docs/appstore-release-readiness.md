## 从开发到发布的验收顺序

1. **工程建立**：确定技术栈与产品范围，创建独立 App 工程；记录构建命令、依赖、Scheme 和版本号。
2. **本地可运行**：完整 Xcode 下完成模拟器构建；核心流程有可重复的验证步骤。
3. **首版可用**：后端上线，真机验证问答、引用、隐私同意、删除及错误处理；检查日志与客户端无服务端密钥。
4. **CI 可重复**：PR 自动构建与适当测试；固定所需工具版本，失败停止后续流程。
5. **TestFlight**：会员、Bundle ID、App 记录和签名就绪；配置受控密钥，再构建上传并在真机安装验收。
6. **商店审核**：资料完整、隐私声明与实现一致、审核期间服务可用；选择已验收构建提交审核。
7. **正式发布**：处理审核反馈，按选定模式发布；保留 commit、版本、build、测试结果和商店状态。

正式发布自动化应在首个 TestFlight 构建跑通后实现。没有工程时不创建带虚构 Scheme、Bundle ID 或签名参数的工作流。
