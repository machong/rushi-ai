# 来源与资料使用政策

**新增约定（2026-11-08）：** 经义解释和标准答案须依据用户认可老师的实际讲解，不采用 AI 按经文字面自拟的释义；没有讲解则待补。具体见[讲解依据约定](commentary_policy.md)及[资料线索](commentary_sources.md)。

本文件将[训练方法](training_method.md)中的来源要求落实为资料登记与审核步骤。用于项目内部审核，不代表已对任何具体资料作出授权结论。

## 1. 来源分类与归属

分别记录经典原文（sutra）、注疏（commentary）、当代讲解（video_lecture 等）和项目原创内容。每份资料保留作者或讲者、版本、宗派或解释传统；未知信息标记为待核实，不猜测补全。

原文、转录、校订稿、通俗解释和 AI 拟答应能相互区分。当代讲解不能标为佛陀原话；AI 拟答不能自动成为审核通过的参考答案。

## 2. 来源登记

在 `data/sources/` 为每个来源保存一份记录，建议包括：

| 字段 | 内容 |
| --- | --- |
| source_id | 稳定来源标识 |
| source_type | 经典、注疏、视频讲解或原创情境 |
| title / creator | 标题、作者或讲者、频道 |
| source_url | 可核查的原始链接 |
| version / published_at | 版本、发布日期或录制日期；未知时明确说明 |
| locator | 经号、卷次、段落，或视频起止时间戳 |
| tradition | 宗派、注释传统或解释立场 |
| license_status | pending / permitted / prohibited / original_example |
| license_evidence | 许可原文、链接或授权证明在本机的位置 |
| permitted_uses | 是否允许获取、转录、训练、公开原文及发布衍生成果，分别记录 |
| obligations | 署名、分发及其他适用条件 |
| checked_at / checked_by | 核验日期与审核人 |
| local_files | 原始材料、转录与校订稿的本机路径 |
| notes | 不确定事项、隐私处理与已知限制 |

素材来源记录与问答审核记录通过稳定标识、链接或审核意见关联。当前程序不会自动校验这份来源档案，须人工确认两者一致。

## 3. 使用状态

- `pending`：来源或使用范围待核实，仅登记为候选，不进入训练导出。
- `permitted`：人工已确认本次训练所需的使用权限，并留存依据。是否允许公开分发仍须单独记录。
- `prohibited`：已知不允许本次用途，不进入训练集。
- `original_example`：字段演示或原创草稿的标记，不表示已通过质量审核；当前导出工具会拒绝。

公开可见、可以下载、可以转录，与允许模型训练或公开分发是不同事项。不能仅凭网站名称、模型卡标签或他人的转发推定所有材料均可使用；按具体版本和计划用途核实。

## 4. 经典与视频处理

经典需记录版本、经号、卷次及上下文，引用逐字核对。注释、译文、校勘与网站整理内容的来源和使用条件分别记录。

视频需记录原始 URL、标题、讲者、日期、时长、字幕类型与许可依据。确认有权处理后，先对小片段测试字幕提取、OCR 或 ASR，再人工校对术语、断句与时间戳。无法辨认之处标记 uncertain，不将推测内容当作讲者原话。

保留未修改的原始转录和校订记录；问答必须能追溯到实际片段。涉及私人案例时移除姓名、联系方式及不必要的敏感细节，并检查组合信息是否仍可识别当事人。

## 5. 进入训练与公开前的检查

1. 核对来源、定位、解释层次和训练使用依据。
2. 按[审核标准](review_rubric.md)完成内容审核，分别记录审核结论与许可结论。
3. 只有 `review_status=approved` 且 `license_status=permitted` 的记录可进入当前导出流程；还需满足来源定位与数据集划分检查。
4. 导出保存审核快照与哈希；修订后生成新版本，不覆盖旧结果。
5. 公开代码、数据、模型或适配器前，分别核对相关许可、署名与隐私要求。训练许可不自动表示允许公开全部素材。

`data/` 中的真实素材、审核记录以及模型和运行产物默认留在本机。Git 忽略规则只防止常见误提交，不能替代人工检查。

发现来源、授权或内容错误时，暂停使用相关样本，保留问题记录与旧版本关联，并检查哪些数据版本、训练运行和适配器受影响。修订后重新审核。
